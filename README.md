# Task Manager

Приложение для собственного сервера, которое читает ваши сообщения в Telegram, с помощью локальной AI-модели находит задачи, адресованные лично вам, и готовит по ним черновики задач для Jira. Каждый черновик вы проверяете сами: без вашего подтверждения в Jira ничего не попадает.

> **Статус: личный проект, работает у автора на Windows.** Все компоненты подключены и проверены на реальных Telegram и Jira, кроме нескольких веток экспорта: загрузка файлов, блоки кода, дополнение задач и проверка запрещённых статусов пока запускались только на тестовом сервере.

## Как это будет работать

```
Telegram → collector → БД → anonymizer → analyzer → review_bot → jira_export → Jira
                                             │           │
                                        Ollama (локально)  подтверждение в личном боте
```

| Компонент | Назначение | Состояние |
|---|---|---|
| `collector` | Читает сообщения из чатов белого списка, в реальном времени и из истории | Работает |
| `storage` | Хранит сообщения, метаданные вложений и очередь обработки | Работает |
| `anonymizer` | Заменяет персональные данные псевдонимами перед передачей модели | Работает |
| `analyzer` | С помощью модели находит задачи и собирает черновики в БД | Работает |
| `review_bot` | Присылает черновик: создать, править или отклонить | Работает |
| `jira_export` | Создаёт задачи в Jira Cloud и дополняет их по вашему решению | Работает |

Задача считается вашей, если выполняется хотя бы одно из условий:

- вас упомянули тегом или по имени;
- сообщение пришло в личку;
- это ответ на ваше сообщение;
- задача адресована фронтенду;
- задача относится к разделу из `config/scope.yaml`.

## Быстрый старт

Нужны Windows, [Docker Desktop](https://www.docker.com/products/docker-desktop/) с WSL2, PowerShell 7 и Ollama. Команды выполняются из папки проекта. Для краткости ниже `tm` означает `pwsh scripts\tm.ps1`.

```powershell
tm secrets generate-key        # ключ базы
tm secrets export-recovery     # сохраните его в менеджере паролей
tm secrets edit chats.yaml     # белый список чатов, образец в config/chats.example.yaml
tm secrets edit me.yaml        # как вас называют, образец в config/me.example.yaml
tm secrets edit scope.yaml     # ваша роль и разделы, образец в config/scope.example.yaml
tm secrets edit jira.yaml      # проект Jira, образец в config/jira.example.yaml
tm secrets set bot_token       # и остальные, список: tm secrets list
tm telegram-login              # вход в Telegram, в вашем терминале
tm start
tm autostart on
```

Запуск прошёл успешно, если все сервисы в статусе `healthy`, а бот прислал «Система запущена».

| Действие | Команда |
|---|---|
| Запустить | `tm start` |
| Остановить сервисы, данные остаются | `tm stop` |
| Остановить ещё Ollama и Docker Desktop, чтобы освободить видеокарту и память | `tm stop -All` |
| Перезапустить, например после правки настроек | `tm restart` |
| Посмотреть состояние | `tm status` |
| Посмотреть логи сервиса | `tm logs collector` |
| Включить или выключить автозапуск | `tm autostart on`, `tm autostart off` |
| Сделать резервную копию | `tm backup` |

**Автозапуск.** Система поднимается при входе в Windows, потому что Docker Desktop без входа не работает. Автовход не настроен намеренно: он отдал бы ключ любому, кто включит ПК. После `tm stop` система сама не поднимется, даже после перезагрузки, пока вы не выполните `tm start`. Сообщения за время простоя дочитываются при запуске.

## Подключение Telegram

Сбор работает от имени вашего аккаунта, потому что бот не видит ваши личные чаты и чужие группы. Сессия только читает: ничего не отправляет и не отмечает прочитанным.

1. **Получите ключи.** На [my.telegram.org](https://my.telegram.org) в разделе API development tools создайте приложение и скопируйте `api_id` и `api_hash`.
2. **Сохраните ключи:** `tm secrets set tg_api_id`, `tm secrets set tg_api_hash`. Ввод скрыт, значения доступны только контейнеру `collector`.
3. **Войдите в аккаунт.** Телефон, код и пароль 2FA вводятся в вашем терминале:
   ```powershell
   tm telegram-login
   ```
4. **Выберите чаты.** Команда выводит ID, тип и название ваших чатов. Нужные ID, в том числе ID личек, впишите через `tm secrets edit chats.yaml`:
   ```sh
   docker compose run --rm --no-deps collector python -m task_manager list-chats
   ```
5. **Запустите сбор:** `tm start`.

Сессия даёт полный доступ к вашему аккаунту, поэтому файла сессии на диске нет: она хранится зашифрованной и передаётся только контейнеру `collector`, в память. Отозвать её можно в Telegram: Настройки → Устройства.

### Как собираются сообщения

- **Белый список:** читаются только чаты из `config/chats.yaml`, личные переписки тоже.
- **Первое чтение чата:** загружается история за `HISTORY_DEPTH_DAYS` дней со статусом `archived`. Она хранится для разметки, но в анализ не идёт.
- **Новые сообщения:** приходят в реальном времени со статусом `pending`.
- **Простой и потеря связи:** при запуске, при переподключении и раз в 5 минут читается всё новее курсора, поэтому сообщения не теряются. Правки старых сообщений за время простоя не отслеживаются.
- **Правки:** текст обновляется. Если содержимое изменилось, сообщение возвращается в очередь, кроме `archived`.
- **Удалённые в Telegram сообщения:** остаются в БД.
- **Ссылки:** есть только у супергрупп и каналов. У личек и обычных групп поле `link` пустое.

## Обезличивание

Модель получает только обезличенный текст. Сервис `anonymizer` хранит такую версию для каждого сообщения. Если обезличить сообщение не удалось, версии нет и модели передавать нечего: исходный текст дальше не идёт.

| Что найдено | Чем заменяется | Можно восстановить |
|---|---|---|
| Вы: имя из `config/me.yaml` в любом падеже, ваш `@username` | `<ME>` | Не требуется |
| Люди, `@username` | `<PERSON_3>` | Да |
| Организации, места | `<ORG_1>`, `<LOC_2>` | Да |
| Организации из `config/me.yaml`, в любом написании | Один `<ORG_n>` на все написания | Да |
| Телефоны, email, ссылки, IP | `<PHONE_1>`, `<EMAIL_1>`, `<URL_1>`, `<IP_1>` | Да, у ссылок без параметров и логина |
| ИНН, IBAN, паспорта, СНИЛС, длинные номера | `<ID_1>` | Да |
| Пароли, токены, ключи, логины (`логин: x / y`, `curl -u x:y`, слова из `secrets`) | `<SECRET>` | **Нет**, значение нигде не сохраняется |
| Номера банковских карт | `<CARD>` | **Нет**, значение нигде не сохраняется |

Один человек получает один и тот же плейсхолдер во всех чатах и падежах. Слова «мы», «нас», «нам» и «нами» не заменяются: они не доказывают, что обращаются именно к вам.

**Что не заменяется.** Термины из `config/scope.yaml` и список `allow` в `config/anonymizer.yaml`, например `Jira`. Пути из `scope.yaml` остаются читаемыми и внутри ссылки: `<URL_1>/blog`. 

| Что нужно | Где это настроить |
|---|---|
| Обычное слово заменяется зря | Кнопка «Это не имя» в боте: слово сохранится в БД, список виден в `/overrides`. Общий список: `allow` в `config/anonymizer.yaml` |
| Имя пропускается | `names` в `config/anonymizer.yaml` |
| Организацию нужно заменять всегда, в том числе сокращённые и английские написания | `organizations` в `config/me.yaml` |
| Один человек получил разные плейсхолдеры, например тег и имя | `same_people` в `config/me.yaml` |
| Логин или пароль, который встречается в чатах в необычной форме | `secrets` в `config/me.yaml` |

`me.yaml` содержит ваше имя, название компании и секреты, поэтому хранится зашифрованным. Редактируется через `tm secrets edit me.yaml`, файл на время правки открывается в блокноте. После изменения выполните `tm restart`: все сообщения пересоберутся автоматически.

**Имена людей.** `collector` при запуске читает участников чатов белого списка. Это нужно, чтобы находить имена, написанные строчными, и тех, кто в чате молчит. Полные и уменьшительные формы распространённых имён, например «Дмитрий» и «Дима», объединяются для таких людей автоматически. Если чат скрывает участников, он пропускается.

**Ограничение.** Автоматическое обезличивание не даёт полной гарантии. Чтобы не заменять сленг и обычные слова, автоматика доверяет только словарю имён, поэтому может пропустить незнакомого человека, который не состоит в ваших чатах: редкое имя в начале фразы, имя, совпадающее с обычным словом («Роман»), или необычное имя строчными. Таких людей можно добавить в `names`. Двойные имена вроде «Анна-Мария» намеренно не распознаются: они встречаются очень редко, а составные слова вроде «мини-попап» часто. Одиночное латинское слово автоматика не считает организацией, потому что обычно это инструмент, поэтому организации с такими названиями стоит указать в `organizations`. Пароль без понятной формы записи автоматика тоже не распознает, для этого есть `secrets`. Поэтому обезличенные тексты и созданные из них датасеты тоже считаются чувствительными. Содержимое вложений не обезличивается и модели не передаётся.

### Как проверить результат на своих сообщениях

```sh
docker compose run --rm --no-deps -v "${PWD}/temp:/out" anonymizer python -m task_manager anonymize-preview /out/anonymizer_preview.md
```

Команда выводит только счётчики, а примеры «было → стало» записывает в файл. В нём настоящая переписка, поэтому удалите его после просмотра. Подойдут `.md` и `.txt`. В `.md` сообщения идут в блоках кода, поэтому `<ME>` и `<SECRET>` видны в любом просмотрщике. HTML команда не принимает: браузер скрыл бы их как теги.

## Подбор модели

Модель работает через [Ollama](https://ollama.com), установленную прямо в Windows, чтобы использовать видеокарту. Текст передаётся только обезличенным и не должен покидать компьютер, поэтому облачные модели Ollama отключены.

### Установка Ollama

Модели занимают десятки гигабайт, поэтому заранее укажите для них диск с достаточным местом. В PowerShell:

```powershell
[Environment]::SetEnvironmentVariable('OLLAMA_MODELS', 'D:\ollama\models', 'User')
[Environment]::SetEnvironmentVariable('OLLAMA_NO_CLOUD', '1', 'User')
winget install --id Ollama.Ollama --location 'D:\ollama\app'
[Environment]::SetEnvironmentVariable('TM_OLLAMA_APP', 'D:\ollama\app\ollama app.exe', 'User')
ollama pull gemma4:12b
```

Проверьте результат:

- `ollama ps` при работающей модели показывает `100% GPU`;
- `%LOCALAPPDATA%\Ollama\server.log` содержит `Ollama cloud disabled: true`;
- сервер слушает только `127.0.0.1:11434`. Контейнеры обращаются к нему через `host.docker.internal`. Менять адрес на `0.0.0.0` не нужно.

Ollama запускается при входе в Windows и держит модель в видеопамяти только во время работы и несколько минут после. Отключить автозапуск можно в диспетчере задач, на вкладке автозагрузки.

### Оценка на своих сообщениях

Выборка, разметка и ответы модели лежат в `eval/dataset/` и `eval/results/`, вне git: обезличенный текст остаётся чувствительным. Команды выводят только счётчики и проценты.

1. Создайте выборку, контейнер `anonymizer` должен работать:

   ```sh
   docker compose run --rm --no-deps -v "${PWD}/eval/dataset:/out" anonymizer python -m task_manager eval-sample /out
   ```

2. Откройте `eval/dataset/labeling.html` двойным щелчком. Клавиши `1`–`5` ставят метку, стрелки листают сообщения. Скачайте результат кнопкой на странице и положите его как `eval/dataset/labels.json`.

   | Клавиша | Метка | Как она считается |
   |---|---|---|
   | `1` | Задача мне | Модель должна её найти |
   | `2` | Возможно мне | Черновик считается ошибкой, пропуск не считается |
   | `3` | Задача, но не мне | Черновик считается ошибкой |
   | `4` | Не задача | Черновик считается ошибкой |
   | `5` | Часть задачи: само сообщение не задача, но обсуждение ведёт к ней | Не считается ни ошибкой, ни находкой |

   Чтобы перепроверить разметку или обновить текст и белый список, сохранив метки, добавьте к команде из шага 1 флаг `--refresh`. Страница откроется с уже поставленными метками.

3. Разделите данные и сравните модели на части для настройки:

   ```sh
   uv run python eval/run_eval.py split
   uv run python eval/run_eval.py run --model gemma4:12b --prompt config/prompts/task_v4.md
   uv run python eval/run_eval.py report
   ```

   Прерванный прогон продолжается с места остановки. Ответы привязаны к содержимому промпта, поэтому изменённый промпт считается заново.

4. Проверьте выбранное сочетание на финальной части (`run --part final`) один раз и просмотрите описания (`review --out temp/descriptions.md`). Если менять промпт после финальной проверки, цифры окажутся завышены, и отчёт об этом предупредит.

### Выбранная модель

Используется `gemma4:12b` с промптом `config/prompts/task_v4.md`, без порога уверенности. Результат на финальной части (88 сообщений):

| Показатель | Значение | Интервал | С поправкой на всю переписку |
|---|---|---|---|
| Precision | 78,9% (15 из 19) | 57–91% | 82,7% |
| Recall | 83,3% (15 из 18) | 61–94% | 84,7% |

Цель по precision была 85%, и она не подтверждена. Результат принят, потому что каждый черновик проходит ручную проверку: лишний черновик легко отклонить, а пропущенная задача теряется. На части для настройки `qwen3:14b` и `gpt-oss:20b` с тем же промптом показали заметно более низкие результаты.

## Поиск задач

`analyzer` разбирает новые сообщения по порядку отправки. Старая история (`archived`) в анализ не попадает.

1. **Префильтр** отсекает только заведомый шум: пустой текст, одни эмодзи и короткие ответы из `config/analyzer.yaml`. Пропустить задачу хуже, чем лишний раз спросить модель.
2. **Модель** получает обезличенное сообщение с контекстом и отвечает: задача или нет. Порога уверенности и списка «возможно, задача» нет.
3. **Ваши сообщения** проверяет отдельный промпт: задачей считается только обещание сделать работу.
4. **Объединение.** Части одной задачи собираются в один черновик в пределах чата и 24 часов: по ответам на его сообщения, по общим основаниям, а если связи нет, решает модель. Ответ на сообщение черновика, который сам не задача, добавляется как уточнение. Текст черновика после этого пересобирается.

Дубли одной задачи из разных чатов не объединяются. Черновики приходят в бота (см. «Ревью-бот»). Посмотреть их файлом тоже можно:

```sh
docker compose run --rm --no-deps -v "${PWD}/temp:/out" analyzer python -m task_manager drafts-preview /out/drafts.md
```

Файл содержит обезличенную переписку, в консоль выводятся только счётчики.

**Без Ollama** ничего не теряется: сообщения ждут в очереди, сбор продолжается, а сервис остаётся здоровым. **Неверный ответ модели** запрашивается ещё два раза, затем сообщение получает статус `failed`. Вернуть такие сообщения в очередь:

```sh
docker compose run --rm --no-deps analyzer python -m task_manager analyze-retry
```

**Проверка на истории.** Команда прогоняет те же шаги на временной копии БД. Рабочая база не меняется, копия удаляется в конце. Около 30 минут на 1900 сообщений:

```sh
docker compose run --rm --no-deps -v "${PWD}/temp:/out" analyzer python -m task_manager analyze-replay /out/replay.md [--days N]
```

**Чат убран из белого списка.** Его новые сообщения не собираются, но ожидающие остаются в очереди. Убрать их, ничего не удаляя:

```sh
docker compose run --rm --no-deps collector python -m task_manager archive-unlisted
```

### Качество на ваших сообщениях

Промпт обещаний оценён на 50 размеченных сообщениях: precision 77,8% (14 из 18), recall 87,5% (14 из 16). Отложенной части нет, а промпт настраивался на этих же сообщениях, поэтому цифры оптимистичны. Команды `eval-sample-own`, `run_eval.py own-run`, `own-report` и `own-errors` повторяют проверку на данных в `eval/dataset/own/`.

## Ревью-бот

Черновики приходят в ваш личный бот по мере появления, а после простоя приходит всё накопленное. Бот работает через long polling, порты наружу не открываются, и отвечает только вам.

### Подключение

1. Создайте бота в [@BotFather](https://t.me/BotFather) и получите токен.
2. Сохраните значения: `tm secrets set bot_token`, `tm secrets set bot_owner_id`. Они доступны только контейнеру `review_bot`. Если ID не совпадёт с аккаунтом, который читает `collector`, сервис не запустится.
3. Откройте бота и нажмите **Start**: первым написать вам он не может.

### Что можно делать

| Кнопка | Что происходит |
|---|---|
| ✅ Создать | Задача принята. Если в тексте остались плейсхолдеры, бот сначала покажет, что подставится в Jira. `<SECRET>` и `<CARD>` нужно убрать: их значение нельзя восстановить |
| ❌ Отклонить | Нужна причина: не задача, не мне, дубль, не актуально, другое. У «другое» текст необязателен |
| ✏️ Править | Заголовок, описание, приоритет, срок. Имена можно оставлять как `<PERSON_N>`. Если вы написали имя, бот предложит заменить его на плейсхолдер |
| ✨ Попросить модель | Вы пишете, что изменить, модель предлагает новый текст. Черновик меняется только после «Принять» |
| 📄 Источник | Исходные сообщения с настоящими именами |
| 🏷 Плейсхолдеры | Отметить ложное срабатывание обезличивания: «Это не имя». Слово станет читаемым везде, снять отметку можно в `/overrides`. Контакты, ссылки, секреты и настоящих людей отметить нельзя |
| 📎 Вложения | Список файлов: любой можно исключить из задачи или посмотреть кнопкой 👁. Голосовые и аудио не показываются |

Изменённая задача всегда уходит вниз чата без звука, а старая карточка удаляется.

Команды есть в кнопке меню рядом с полем ввода: `/list` нерешённые задачи, `/status` очередь и модель, `/overrides` отмеченные слова, `/clear` очистить переписку, `/export_old` задачи, принятые до подключения Jira. `/clear` не меняет статусы задач. Нерешённую задачу можно снова открыть через `/list`. Сообщения старше 48 часов Telegram удалить не даёт.

### Если задача получила продолжение

| Статус задачи | Что происходит с новым связанным сообщением |
|---|---|
| Не решена | Задача молча дополняется. Текст, который вы правили, не перезаписывается: задача лишь покажет, что есть новые сообщения |
| Принята | Модель решает, нужен ли запрос на изменение. Что с ним делать, решаете вы (см. «Экспорт в Jira») |
| Отклонена | Модель решает, нужно ли вернуть задачу, учитывая причину отклонения |

При сомнении модель создаёт тикет: пропустить изменение хуже, чем отклонить лишнее. Связанным считается ответ на сообщение задачи, сообщение с общими основаниями или, для сообщения-задачи, то, что модель сочла той же работой. Уточнение без такой связи до вас не дойдёт.

Решения можно выгрузить как метки для будущей оценки: `python -m task_manager feedback-export FILE`.

## Экспорт в Jira

Принятая задача уходит в Jira сама, обычно в течение 15 секунд. Задача без спринта попадает в бэклог. Если Jira недоступна, задача ждёт в очереди и ничего не теряется. Токен доступен только контейнеру `jira_export`.

### Подключение

1. Сохраните адрес, почту и [API-токен](https://id.atlassian.com/manage-profile/security/api-tokens): `tm secrets set jira_url`, `jira_email`, `jira_api_token`. Токен имеет срок действия: когда он истечёт, бот один раз сообщит об этом.
2. Опишите проект: `tm secrets edit jira.yaml`, образец в `config/jira.example.yaml`.
3. Запустите систему: `tm start`.

При запуске сервис сверяет тип задачи и запрещённые статусы с проектом. При несовпадении он завершается с кодом 2 и называет расхождение, поэтому опечатка в статусе не отключит запрет молча.

Задачи, принятые до подключения, сами не отправляются. Их можно отправить по одной через `/export_old`.

### Что уходит

| В Jira | Откуда |
|---|---|
| Заголовок и описание | Текст черновика. Оставшиеся `<PERSON_N>` и другие плейсхолдеры заменяются настоящими значениями, `<ME>` становится «я». Бот показывает подстановку до подтверждения |
| Блоки кода | Сниппеты из сообщений задачи, дословно. Пароли, номера карт и параметры ссылок скрываются, и бот сообщает об этом |
| Исполнитель | Вы |
| Приоритет | По `priorities` в конфиге |
| Срок | Только дата, которую вы указали сами: вычисления дат у модели ненадёжны |
| Вложения | Изображения, файлы и видео из сообщений задачи. Голосовые и аудио не уходят, стикеры и GIF включаются вручную. Файлы не обезличиваются, а на диске хранятся только до загрузки |

Ссылки на сообщения в Jira не передаются.

### Запрос на изменение

Задачи, над которыми вы работаете, без вашего нажатия не меняются.

| Статус исходной задачи | Что происходит |
|---|---|
| «Новая» и другие из `auto_append_statuses` | Дополняется сама, бот сообщает об этом. Исключение: в запросе есть плейсхолдеры или файлы. Тогда кнопки, как в следующей строке, потому что настоящие значения и файлы вы должны увидеть до отправки |
| «В плане», «В работе», «На доработке», «На проверке» | ➕ Дополнить или 🆕 Новая задача |
| «Готово», «Тестирование» и другие из `locked_statuses` | Только новая задача. Исходная не меняется никак, даже связью: новая просто упоминает её в тексте |

Дополнение добавляет к описанию раздел «Изменение от ДД.ММ» и не трогает прежний текст, поэтому правки в самой Jira не теряются. Статус проверяется ещё раз прямо перед записью. Если задача успела перейти в запрещённый статус, ничего не меняется, а бот предложит создать новую.

### Если что-то пошло не так

| Что произошло | Что делает система |
|---|---|
| Истёк токен (401, 403) | Одно сообщение в боте, экспорт ждёт |
| Jira недоступна (5xx, сеть) | Повторяет сама |
| Jira отказала в задаче (400) | Бот показывает код и поле, кнопка «Повторить» |
| Файл не загрузился | Задача остаётся, бот называет файл, кнопка повторит только файлы |
| Сбой сразу после создания | Перед повтором ищет вашу задачу с таким же заголовком за 3 дня, поэтому дубль маловероятен. Если индекс Jira не успел обновиться за 2 минуты, дубль возможен |

### Файлы конфигурации

Сервисы читают настройки при запуске, поэтому после изменений выполните `tm restart`. Файлы с личными данными хранятся зашифрованными и редактируются через `tm secrets edit`, остальные лежат в `config/`.

| Файл | Назначение | Обязателен | В git |
|---|---|---|---|
| `chats.yaml` | Белый список чатов | Да | Нет, зашифрован, образец в `chats.example.yaml` |
| `scope.yaml` | Ваша роль и разделы с синонимами | Да | Нет, зашифрован, образец в `scope.example.yaml` |
| `jira.yaml` | Проект Jira, тип задачи, запрещённые статусы, приоритеты | Да, для `jira_export` | Нет, зашифрован, образец в `jira.example.yaml` |
| `me.yaml` | Как вас называют в чатах | Да, для `anonymizer` | Нет, зашифрован, образец в `me.example.yaml` |
| `anonymizer.yaml` | Общий список разрешённых слов и дополнительные имена. Ваши слова хранятся в БД | Да, для `anonymizer` | Да |
| `analyzer.yaml` | Короткие ответы, которые не отправляются модели | Да, для `analyzer` | Да |
| `prompts/` | Промпты для модели, только с вымышленными примерами | Да, для `analyzer` и оценки | Да |

**`chats.yaml`.** ID чатов не должны повторяться:

```yaml
chats:
  - id: -1001234567890
    title: Пример чата   # необязательно
```

**`scope.yaml`.** Чтобы расширить зону ответственности, добавьте термин или раздел, менять код не нужно. У каждого раздела должен быть хотя бы один синоним:

```yaml
role:
  - фронтенд
sections:
  - name: Статьи
    aliases:
      - блог
      - /blog
```

Если в файле ошибка, сервис не запускается и в логах контейнера указывает файл и причину. Неизвестные ключи тоже считаются ошибкой, чтобы опечатка не осталась незамеченной.

## Разработка

Нужен [uv](https://docs.astral.sh/uv/). Подходящую версию Python (3.12) он установит сам.

```sh
uv sync                     # установить зависимости
uv run pytest               # все тесты
uv run pytest tests/test_config.py::test_unknown_key_is_rejected   # один тест
uv run ruff check .         # проверка кода
uv run ruff format .        # форматирование
```

Коммиты оформляются по [Conventional Commits](https://www.conventionalcommits.org/ru/), например `feat(storage): ...`.

### Миграции БД

Схема описана в `src/task_manager/storage/models.py`. После её изменения создайте миграцию:

```sh
uv run alembic upgrade head                                       # подготовить локальную БД в data/app.db
uv run alembic revision --autogenerate -m "описание изменения"    # создать миграцию
```

Проверьте созданный файл в `storage/migrations/versions/`. В контейнерах миграции применяет сервис `migrate` при каждом запуске. Если модели и миграции разойдутся, тест `test_models_match_migrations` упадёт.

## Документация

### Сервисы и контейнеры

Все сервисы собираются из одного образа и работают в отдельных контейнерах, поэтому сбой одного не останавливает остальные.

Сначала выполняется разовый сервис `migrate`, и только после его успешного завершения стартуют остальные. Запуск и проверка сервиса выполняются так:

```sh
python -m task_manager run <service>      # collector, anonymizer, analyzer или review_bot
python -m task_manager health <service>   # проверка состояния вручную
python -m task_manager.health <service>   # то же без загрузки приложения, для healthcheck в Docker
python -m task_manager login              # вход в Telegram, обычно через tm telegram-login
python -m task_manager list-chats         # список ваших чатов
python -m task_manager drafts-preview FILE     # черновики и их сообщения в файл
python -m task_manager analyze-retry           # вернуть упавшие сообщения в очередь
python -m task_manager analyze-replay FILE     # прогон истории на временной копии БД
python -m task_manager archive-unlisted        # убрать из очереди чаты вне белого списка
```

| Код выхода | Значение |
|---|---|
| `0` | Штатное завершение, или сервис здоров (`health`) |
| `1` | Сбой при работе: например, недоступна БД или не применены миграции. Для `health`: сервис нездоров |
| `2` | Ошибка конфигурации: неверный файл, нет ключей или сессии Telegram |

Работающий сервис каждые 10 секунд проверяет БД и обновляет файл состояния. Сервис считается здоровым, если файл обновлялся не позже чем 30 секунд назад.

### База данных

SQLite с режимом WAL, потому что в один файл пишут несколько контейнеров. Файл лежит в томе Docker `app_data`, а не в папке проекта: когда папка Windows подключена в контейнер, блокировки SQLite работают ненадёжно. Время хранится в UTC.

| Таблица | Содержимое |
|---|---|
| `chats` | ID, название и тип чата, курсор `last_msg_id`, с которого продолжается чтение, и отметка `history_loaded_at` о загрузке истории |
| `messages` | Сообщение, его отправитель, даты отправки и правки, ссылка, флаги `mentions_me` и `is_outgoing`, статус обработки. Пара `chat_id` и `msg_id` уникальна |
| `attachments` | Метаданные вложений: тип, имя и его обезличенная версия, размер. Сами файлы не хранятся |
| `people` | Люди из Telegram: ID, имя, фамилия, `@username`, признак «это я». Нужны, чтобы находить имена в тексте |
| `pseudonyms` | Карта замен: плейсхолдер и настоящее значение. Такая же чувствительная, как исходный текст |
| `anonymized_messages` | Обезличенный текст сообщения, отправитель-плейсхолдер, хеш исходного текста и версия правил |

Поле `messages.status` служит очередью обработки и принимает значения `pending`, `processing`, `done`, `failed` и `archived`. Сообщения `archived` в очередь не попадают.

### Логи

Логи пишутся в JSON. Чтобы текст сообщений не попал в них, форматтер записывает только название события и поля из списка `ALLOWED_FIELDS` в `common/log.py`. Аргументы вида `%s` и текст исключений отбрасываются, от исключения остаются только его тип и стек.

```python
logger.info("message_saved", extra={"chat_id": chat_id, "msg_id": msg_id})  # правильно
logger.info(f"Получено: {text}")  # нельзя: текст попадёт в лог
```

## Безопасность

- **Порты:** контейнеры не открывают порты наружу.
- **Контейнеры:** работают не от root и с файловой системой только для чтения.
- **Только чтение в Telegram:** весь доступ идёт через обёртку `collector/telegram.py`, а тесты запрещают операции записи и отметку о прочтении.
- **Обезличивание:** модель читает текст только через функцию, которая отдаёт актуальную обезличенную версию. Пароли, токены и номера карт нигде не сохраняются в карте замен.

### Шифрование

| Что | Как хранится |
|---|---|
| База, включая текст сообщений и карту замен | SQLCipher: зашифрован весь файл. Без ключа сервис не запустится |
| Ключ базы, токены, сессия Telegram, `me.yaml`, `chats.yaml`, `scope.yaml`, `jira.yaml` | DPAPI Windows в `%LOCALAPPDATA%\task-manager\secrets`, расшифровывается только под вашей учётной записью |
| Секреты в контейнерах | Только в памяти, и каждый контейнер видит только свои. На диске Docker и в `docker inspect` их нет |
| Файлы вложений на время передачи | Только в памяти |
| Резервные копии | Зашифрованы тем же ключом, лежат в папке `TM_BACKUP_DIR` |
| Данные оценки | Зашифрованный `eval/archive.db`, копия в папке резервных копий. Для работы: `tm eval open`, после неё `tm eval seal` |

**От чего это защищает:** от кражи выключенного ПК, если у входа в Windows есть пароль, и от утечки копий и файлов.

**От чего не защищает:** от того, кто работает за включённым ПК под вашей учётной записью, и от вредоносной программы под ней: система должна запускаться сама, поэтому ключ ей доступен. Если диски не зашифрованы, важно иметь надёжный пароль Windows. PIN защищает только вход на этом устройстве, а расшифровка DPAPI привязана к паролю учётной записи.

**Ключ восстановления.** После переустановки Windows DPAPI не расшифрует хранилище. Без копии ключа из `tm secrets export-recovery` база и резервные копии станут нечитаемыми.

### Мониторинг

Бот сообщает, если сервис молчит больше 3 минут, нет связи с Telegram, очередь стоит больше часа, модель недоступна, экспорт в Jira падает или истёк токен. Каждое предупреждение приходит один раз, а при восстановлении приходит отдельное сообщение.

Раз в 5 минут задача планировщика проверяет то, о чём бот сообщить не может: сам бот, Docker, свободное место на системном диске и диске проекта, возраст резервной копии. Выключенный ПК не виден никому: о простое бот сообщит при следующем запуске. Намеренная остановка через `tm stop` тревог не вызывает.

### Резервные копии

Создаются раз в день в папке `TM_BACKUP_DIR`, лучше на другом физическом диске. Хранятся последние 14. Каждая проверяется чтением сразу после создания. Восстановить: `tm restore <файл>`, скрипт спросит подтверждение.

## Решение проблем

| Симптом | Причина и решение |
|---|---|
| `failed to connect to the docker API` | Docker Desktop не запущен. `tm start` запустит его сам |
| `Configuration error: the database key is missing` | Секреты не загружены, потому что Docker перезапускался. Выполните `tm start` |
| `Configuration error: the database can't be opened with this key` | Ключ не подходит к базе. Восстановите ключ из копии: `tm secrets set database_key` |
| `Ошибка: не заданы секреты` | Задайте их, список покажет `tm secrets list` |
| Сервис постоянно перезапускается | Посмотрите причину: `tm logs <сервис>` |
| В логах `anonymizer` событие `message_anonymize_failed` | Сообщение не передаётся модели. На следующем проходе будет новая попытка, а в логе указан его `msg_id` |
| `Configuration error: no valid Telegram session` | Сессия отозвана. Войдите заново: `tm telegram-login`, затем `tm start` |
| В логах `collector` событие `chat_not_found` | Чата с этим ID нет среди ваших чатов. Сверьте ID с выводом `list-chats`: при преобразовании группы в супергруппу ID меняется |
| В логах `collector` событие `rate_limited` | Telegram просит подождать. Сервис подождёт указанное время и продолжит сам |
| В логах сервиса `service_failed` и `"exc_type": "OperationalError"` | Скорее всего, миграции не применились. Проверьте `docker compose logs migrate` |
